# OKLIN 3 manual: current implementation and remaining work

Audit date: 6 October 2026. Reference: `BACKEND/Oklin3-Handbuch_V8.0_en.pdf`, **Manual OKLIN 3**, 44 pages, October 2025. Page numbers below are the printed PDF page numbers.

This audit supersedes the older backend implementation maps. A modeled setting, simulated measurement, or visible button is **not** proof of a working production feature. The existing application, routes, four-camera DSM bridge, dataset contracts, UI theme configuration and shared inspection stream were extended, not replaced.

## Intentionally preserved user choices

- Emage branding, Classic/Modern designs, theme profiles, gradients and existing customized colors.
- Adjustable tray capacity, sequential WT numbering, image-led WT View, latest-30 history view and four-channel inspection contract.
- Local BMP/TIFF setup upload instead of camera acquisition; setup uploads do not add inspection WT history.
- Removed Lens Condition text stays removed, even though the manual includes that older control.
- Native algorithm/backend APIs are not rewritten to imitate unsupported machine functions.

## Files and architecture

Frontend changes are concentrated in the existing `InspectionDashboard`, `InspectionCanvas`, `LensViewer`, `TopBar`, `ClassicHeader`, `AppShell`, `ImageFilterWorkspace`, `SettingsWorkspace`, `RegistrationWorkspace`, `FocusWorkspace`, `BvTestWorkspace` and `TrendChart`. Shared API/types and original-image ZIP support were extended.

New frontend helpers: `src/lib/inspection-display.ts`, `inspection-yield.ts`, `image-window.ts`, `open-manual.ts`. New scoped styles: `src/app/settings-manual.css`, `src/components/inspection-manual.css`. Regression coverage: `scripts/check-manual-inspection.cjs`, `check-manual-settings-ui.cjs`, extended `check-shared-inspection-ui.cjs`.

Backend changes: `app/api/routes.py`, `app/models/schemas.py`, `app/main.py`, `app/services/storage_service.py`, `system_state.py`, `registration_service.py`, `report_service.py`. New focused services: `settings_service.py`, `storage_schedule.py`, `statistics_service.py`, `focus_checks.py`, `bv_scripts.py`. Tests: `tests/test_manual_settings.py`, `tests/test_manual_runtime.py`, `tests/test_storage_reliability.py`.

The maintenance task checks recurrence and statistics independently every 15 seconds without blocking the API. An optional statistics-write failure does not abort frame processing. Storage also checks the schedule before each completed frame; counter/runtime UI polls every two seconds where relevant. Recurrence uses the backend machine's local wall clock, while inspection/report/log timestamps are UTC. Missed events are not replayed after a shutdown.

Storage is under the configured backend `STORAGE_ROOT`, except an explicitly configured absolute optimization destination. Deferred optimization images occupy `optimization_pending` until transferred. Source uploads remain in storage. CSV retention and registration-backup pruning affect only files owned by their respective services.

## Verification and rollout

- TypeScript typecheck and isolated production build.
- Backend suite: 60 tests, temporary storage, bridge loading disabled; no production datasets or licenses touched. Includes fault-injection tests for staging rollback, missing transfers, atomic saves and independent maintenance.
- Browser fixture checks: 17 scenarios across independent Classic/Modern clients, late join/reload, held-history release, held manual re-inspection, filtered-canvas/live-gallery independence, sequential tray rollover, stale snapshots, polling fallback, progressive images, pinch without accidental selection, consistent status percentages, cross-illumination DSM overlays, per-head setup results, null Focus geometry and large TIFF setup uploads with no new WT rows. BV canvases are checked for panel containment, visible headers and nested Escape behavior at laptop/tablet sizes. All API writes were intercepted; no browser runtime errors.
- Settings browser checks at 1920×1080, 1366×768 and 1024×768: no horizontal overflow or normal-desktop field scrollbars, live timeout preview, complete saved settings and read-only Operator access.
- Generated Focus report rendered and visually inspected; package ZIP/CSV/original-image contents verified.
- Existing snapshot, preview cache, local preview, inference timing, upload and shared-state unit regressions.

There is no standalone ESLint script configured. The production build/type validation is the available compile check; this is not a claim that a separate lint suite or real machine qualification was run.

Restart/redeploy the backend and rebuild/restart the frontend together to load these changes. Running production processes were not restarted and stored inspection history was not cleared. No new dependencies are required. Next recommended work: agree the per-client authentication design and obtain the real camera/PLC/calibration contracts, then integrate and validate each production adapter explicitly.
